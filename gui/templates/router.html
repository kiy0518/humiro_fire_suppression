전체 시스템 실행 순서
Step 1. SITL PC (Ubuntu) — 192.168.100.100
  1. WiFi 연결 확인
    ping 192.168.100.11 (VIM4 #1 응답 확인)
  2. PX4 SITL 3대 동시 실행
    ~/start_sitl_all.sh
    드론 1,2,3 인스턴스 순차 시작 (10초 간격)
  3. 로그 확인
    tail -f ~/sitl_logs/drone1.log
Step 2. VIM4 보드 — 각 드론 (자동 시작)
  1. micro-ROS Agent (systemd 자동 시작)
    micro_ros_agent.service → UDP :8888 대기
    PX4의 uxrce_dds_client가 연결
  2. MAVLink Router (systemd 자동 시작)
    mavlink-router.service → SITL/FC 모드에 따라 설정
  3. 메인 프로그램 (systemd 또는 수동)
    service-control.sh debug (수동 실행시)
Step 3. GCS (QGroundControl)
  1. WiFi 연결
    동일 네트워크 (192.168.100.x) 접속
  2. QGroundControl 실행
    자동으로 3대 기체 발견 (UDP 14550/14560/14570)
Step 4. 연결 확인
  1. 이 페이지에서 SITL 모드 ON
    상단 "SITL 모드" 토글 활성화
  2. 다이어그램에서 연결 상태 확인
    PC SITL 노드 연결됨 (녹색), 3개 인스턴스 표시
  3. VehicleStatus 수신 확인
    ros2 topic echo /drone1/fmu/out/vehicle_status
주의사항
재시작 규칙: PX4 SITL 또는 micro-ROS Agent 한쪽이 재시작되면, 양쪽 모두 재시작 필요. uXRCE-DDS 세션이 "re-established"되면 토픽이 재생성되지 않음.
SITL 모드 전환: SITL/FC 모드 전환 시 mavlink-router 서비스가 재시작됨. 비행 중에는 절대 전환하지 마세요.
포트 충돌: micro-ROS Agent (UDP 8888)를 수동으로 실행하면 systemd 서비스와 포트 충돌. sudo systemctl stop micro_ros_agent 후 수동 실행하거나, 서비스만 사용.
SITL 배터리: PX4 rcS에서 SIM_BAT_ENABLE 0 설정 필요. 미설정 시 "Battery unhealthy" 오류로 arming 불가.
데이터 흐름 (SITL 모드)
경로 프로토콜 포트 설명
PX4 SITL → VIM4 MAVLink UDP 14540 FC 텔레메트리 (브로드캐스트, mavlink-router가 수신)
PX4 SITL → VIM4 uXRCE-DDS 8888 ROS2 토픽 (VehicleStatus, SensorCombined 등)
VIM4 → PX4 SITL uXRCE-DDS 8888 ROS2 토픽 발행 (TrajectorySetpoint, OffboardControlMode 등)
VIM4 → GCS MAVLink UDP 14550 QGC 텔레메트리 (mavlink-router → QGC)
GCS → VIM4 MAVLink UDP 14553 커스텀 메시지 (60000~60003, 미션 명령)
VIM4 ↔ VIM4 ROS2 DDS - 편대 명령/상태 (FormationCommand, FollowerStatus, DronePosition)

ssh humiro@192.168.100.100 "pkill -f px4"
